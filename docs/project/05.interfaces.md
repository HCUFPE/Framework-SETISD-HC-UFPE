## 2. Hardware

O sistema deve suportar os equipamentos de bancada mais comuns no fluxo de patologia:

- Impressoras térmicas Zebra e Argox para geração automática de etiquetas de frascos, cassetes, blocos e lâminas.
- Leitores de código de barras e QR Code HID (Human Interface Device) que funcionem como teclado virtual, sem necessidade de driver adicional.
- Estações configuráveis por ponto de uso: triagem, macroscopia, processamento e microscopia.

### Requisitos de hardware

- A leitura de QR Code deve ser integrada como entrada de texto padrão nos formulários do sistema.
- A impressão deve aceitar comandos de impressão em ZPL/EPL, com retry automático em caso de falha.
- Cada estação deve ter sua impressora configurada em `IMPRESSORAS` no banco de dados.
- Impressão de etiquetas deve ser registrada em `LOG_IMPRESSOES` para auditoria.

## 3. Software

O software funciona como orquestrador entre três domínios:

1. **Integração com AGHU** para importação de dados de paciente e exame e exportação de registros de macroscopia, laudo prévio e laudo final.
2. **Controle local de rastreabilidade** com modelo hierárquico (frasco → cassete → bloco → lâmina) e histórico de movimentação.
3. **Autenticação LDAP/AD** e controle de acesso por perfis para garantir segurança e conformidade.

### Integração com AGHU

- Importa paciente e exame com base em número de solicitação, CNS, CPF ou leitura de QR Code.
- Armazena os dados importados em `AGHU_SYNC` para manter a visão unificada sem replicar laudos oficiais.
- Sincroniza a realização de macroscopia, a criação de laudo prévio e a liberação de laudo final.
- Trata falhas de conexão com retry automático e marcações de status (`Sucesso`, `Erro`, `Pendente`).

### Autenticação e autorização

- Autenticação via LDAP/AD do hospital.
- Geração de token JWT com renovação por refresh token.
- Perfis suportados: Recepcionista, Macroscopista, Técnico de Laboratório, Residente e Médico Patologista.
- Controle de acesso por rota no backend com base no perfil do usuário.

### Interfaces de integração

O contrato principal de integração do sistema deve ser descrito em TypeScript para documentar a camada de API de terceiros.

```typescript
interface IHospitalApi {
  getPatientData(id: string): Promise<PatientRecord>;
  syncProntuario(data: ProntuarioUpdate): Promise<SyncResponse>;
  checkLdapAuth(credentials: AuthInfo): Promise<AuthStatus>;
}

interface PatientRecord {
  id: string;
  nome: string;
  cns?: string;
  cpf?: string;
  prontuario?: string;
  data_nascimento: string;
  genero?: 'M' | 'F' | 'O';
  dados_clinicos: Record<string, unknown>;
}

interface ProntuarioUpdate {
  id_exame: string;
  numero_solicitacao: string;
  tipo_peça: string;
  topografia: string;
  descricao_macroscopia?: string;
  laudo_previo?: string;
  laudo_final?: string;
  responsavel: string;
  data_operacao: string;
}

interface SyncResponse {
  status: 'Sucesso' | 'Erro' | 'Pendente';
  mensagem?: string;
  data_sync: string;
}

interface AuthInfo {
  username: string;
  password: string;
}

interface AuthStatus {
  authenticated: boolean;
  perfil?: 'Recepcionista' | 'Macroscopista' | 'Técnico de Laboratório' | 'Residente' | 'Médico Patologista';
  token?: string;
  expiresAt?: string;
}
```

### Observações de integração

- O backend deve expor endpoints REST para importação de dados do AGHU, validação de usuários LDAP/AD e controle de impressoras.
- Os endpoints devem ser documentados em OpenAPI / Swagger para facilitar conexão com o frontend.
- A interface TypeScript deve ser usada como contrato principal sempre que houver integração com sistemas externos.

## 4. Alinhamento com os documentos do projeto

- **Visão**: suporta a proposta de rastreabilidade física e visão unificada sem substituir o AGHU como repositório oficial de laudos.
- **Requisitos**: contempla integração com impressoras, leitores de QR Code, AGHU e LDAP/AD, além da necessidade de logs e auditoria.
- **Casos de Uso**: reflete os fluxos de triagem, macroscopia, processamento, microscopia e busca/rastreamento unificado.
- **Banco de Dados**: conecta o modelo físico aos requisitos de `IMPRESSORAS`, `LOG_IMPRESSOES`, `AGHU_SYNC` e `HISTORICO_MOVIMENTACAO`.
