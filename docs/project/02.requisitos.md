# Especificação de Requisitos
## Sistema de Gestão Digital da Anatomia Patológica

---

## 1. Requisitos Funcionais (RF)

### 1.1 Autenticação e Controle de Acesso

| ID | Título | Descrição | Prioridade |
| :--- | :--- | :--- | :--- |
| RF001 | Autenticação via LDAP/AD | O sistema deve autenticar usuários via LDAP/AD do hospital, redirecionando para login em caso de sessão inativa ou inexistente. | Essencial |
| RF002 | Controle de perfis de acesso | O sistema deve suportar perfis distintos: Recepcionista, Macroscopista, Técnico de Laboratório, Residente e Médico Patologista. Cada perfil deve ter acesso apenas às funcionalidades pertinentes ao seu papel. | Essencial |
| RF003 | Logout | O sistema deve permitir que o usuário encerre sua sessão manualmente. | Essencial |
| RF004 | Expiração de sessão | A sessão do usuário deve expirar após período de inatividade configurável, exigindo nova autenticação. | Essencial |

---

### 1.2 Triagem / Recepção

| ID | Título | Descrição | Prioridade |
| :--- | :--- | :--- | :--- |
| RF005 | Identificação da origem da peça | O sistema deve permitir que a recepcionista identifique se a peça é proveniente do SUS ou do HC, direcionando o fluxo adequado. | Essencial |
| RF006 | Cadastro de paciente | Para peças do SUS, o sistema deve permitir o cadastro do paciente com CNS/CPF, verificando se já existe registro antes de criar um novo. | Essencial |
| RF007 | Cadastro de exame no AGHU | O sistema deve permitir o registro do exame no AGHU, vinculando-o ao paciente cadastrado. | Essencial |
| RF008 | Consulta de peça na triagem | Para peças do HC, o sistema deve permitir a recuperação dos dados do paciente e do exame já cadastrados no AGHU por meio da leitura do código de barras via pistola/leitor ou por busca manual via número de solicitação, CNS ou CPF. O escaneamento é o meio preferencial por agilidade, mas não é obrigatório. | Essencial |
| RF009 | Geração de número de solicitação | O sistema deve gerar automaticamente um número único de solicitação para cada peça recebida. | Essencial |
| RF010 | Geração e impressão de etiqueta da peça | O sistema deve gerar e imprimir automaticamente uma etiqueta com QR Code/código de barras vinculada ao número de solicitação, via impressora térmica (Zebra/Argox). | Essencial |
| RF011 | Registro de recebimento da peça | O sistema deve registrar data, hora e responsável pelo recebimento da peça na triagem. | Essencial |
| RF012 | Envio digital do frasco para Macroscopia | O sistema deve registrar o encaminhamento do frasco da triagem para a etapa de macroscopia, atualizando o status da peça. | Essencial |

---

### 1.3 Macroscopia

| ID | Título | Descrição | Prioridade |
| :--- | :--- | :--- | :--- |
| RF013 | Identificação do frasco na macroscopia | O sistema deve permitir a identificação do frasco ao iniciar a macroscopia, exibindo os dados do paciente e do exame importados do AGHU. A identificação pode ser feita por leitura do QR Code/código de barras ou por busca manual via número de solicitação. O escaneamento é o meio preferencial por agilidade, mas não é obrigatório. | Essencial |
| RF014 | Registro da macroscopia | O sistema deve permitir o registro das informações da macroscopia: descrição, data de realização, número de cassetes gerados e responsável. | Essencial |
| RF015 | Geração de cassetes vinculados à peça | O sistema deve permitir a criação de N cassetes vinculados hierarquicamente à peça matriz (relação 1:N), gerando identificador único para cada cassete. | Essencial |
| RF016 | Geração e impressão de etiquetas dos cassetes | O sistema deve gerar e imprimir automaticamente etiquetas com QR Code para cada cassete gerado, via impressora térmica. | Essencial |
| RF017 | Confirmação de identidade dos cassetes | O sistema deve permitir a confirmação da identidade de cada cassete antes do envio para Processamento, por leitura do QR Code ou por busca/seleção manual do identificador do cassete no sistema. O escaneamento é o meio preferencial por agilidade, mas não é obrigatório. | Essencial |
| RF018 | Sincronização com AGHU na macroscopia | O sistema deve registrar no AGHU os dados da macroscopia (descrição, data, número de cassetes) após a conclusão desta etapa. | Essencial |
| RF019 | Envio digital dos cassetes para Processamento | O sistema deve registrar o encaminhamento dos cassetes identificados para a etapa de Processamento Técnico, atualizando o status. | Essencial |

---

### 1.4 Processamento Técnico

| ID | Título | Descrição | Prioridade |
| :--- | :--- | :--- | :--- |
| RF020 | Identificação do cassete no processamento | O sistema deve permitir a identificação do cassete ao iniciar o processamento de tecidos, vinculando a ação ao técnico responsável. A identificação pode ser feita por leitura do QR Code ou por busca/seleção manual do identificador do cassete no sistema. O escaneamento é o meio preferencial por agilidade, mas não é obrigatório. | Essencial |
| RF021 | Registro do processamento de tecidos | O sistema deve registrar a etapa de processamento de tecidos, incluindo data de início, responsável e cassetes processados. | Essencial |
| RF022 | Registro de inclusão em bloco de parafina | O sistema deve registrar a inclusão do tecido em bloco de parafina, vinculando o bloco ao cassete de origem. | Essencial |
| RF023 | Geração de blocos de parafina vinculados ao cassete | O sistema deve permitir a criação de blocos de parafina vinculados hierarquicamente ao cassete (relação 1:N), gerando identificador único para cada bloco. | Essencial |
| RF024 | Registro de corte | O sistema deve registrar a etapa de realização do corte, incluindo data e responsável. | Essencial |
| RF025 | Geração de lâminas vinculadas ao bloco | O sistema deve permitir a criação de N lâminas vinculadas hierarquicamente ao bloco de parafina (relação 1:N), gerando identificador único para cada lâmina. | Essencial |
| RF026 | Registro de coloração e montagem | O sistema deve registrar a etapa de coloração e montagem das lâminas, incluindo data e responsável. | Essencial |
| RF027 | Registro de liberação das lâminas | O sistema deve registrar a liberação das lâminas, incluindo data de liberação, número de lâminas produzidas e técnico responsável. | Essencial |
| RF028 | Geração e impressão de etiquetas das lâminas | O sistema deve gerar e imprimir automaticamente etiquetas com QR Code para cada lâmina produzida, via impressora térmica. | Essencial |
| RF029 | Confirmação de identidade das lâminas | O sistema deve permitir a confirmação da identidade de cada lâmina antes do envio para Microscopia, por leitura do QR Code ou por busca/seleção manual do identificador da lâmina no sistema. O escaneamento é o meio preferencial por agilidade, mas não é obrigatório. | Essencial |
| RF030 | Confirmação de identidade dos blocos de parafina | O sistema deve permitir a confirmação da identidade de cada bloco de parafina antes do arquivamento, por leitura do QR Code ou por busca/seleção manual do identificador do bloco no sistema. O escaneamento é o meio preferencial por agilidade, mas não é obrigatório. | Essencial |
| RF031 | Envio digital das lâminas para Microscopia | O sistema deve registrar o encaminhamento das lâminas identificadas para a etapa de Microscopia, atualizando o status. | Essencial |
| RF032 | Encaminhamento de blocos para arquivamento | O sistema deve registrar o encaminhamento dos blocos de parafina identificados para o arquivo físico. | Essencial |
| RF033 | Recebimento e processamento de pedido de imunohistoquímica/complementos | O sistema deve receber pedidos de imunohistoquímica ou complementos originados na Microscopia, registrá-los e reintroduzi-los no fluxo de processamento a partir da etapa de corte. | Essencial |

### 1.5 Microscopia

| ID | Título | Descrição | Prioridade |
| :--- | :--- | :--- | :--- |
| RF034 | Identificação da lâmina na microscopia | O sistema deve permitir a identificação da lâmina ao iniciar a análise, exibindo os dados do paciente, exame e histórico de processamento importados do AGHU e do sistema. A identificação pode ser feita por leitura do QR Code ou por busca/seleção manual do identificador da lâmina no sistema. O escaneamento é o meio preferencial por agilidade, mas não é obrigatório. | Essencial |
| RF035 | Elaboração de laudo prévio pelo residente | O sistema deve permitir que o residente registre o laudo prévio, vinculado à lâmina e ao exame correspondente. | Essencial |
| RF036 | Registro do laudo prévio no AGHU | O sistema deve sincronizar o laudo prévio elaborado pelo residente com o AGHU. | Essencial |
| RF037 | Revisão do laudo pelo médico patologista | O sistema deve apresentar ao médico patologista os laudos prévios pendentes de revisão, permitindo sua aprovação ou reprovação. | Essencial |
| RF038 | Solicitação de imunohistoquímica/complementos | O sistema deve permitir que o residente registre uma solicitação de imunohistoquímica ou complementos quando o laudo for considerado inacabado pelo patologista, gerando um pedido formal encaminhado ao Processamento Técnico. | Essencial |
| RF039 | Registro da solicitação de complementos no sistema | O sistema deve registrar a solicitação de imunohistoquímica/complementos com data, solicitante e exame vinculado. | Essencial |
| RF040 | Registro do laudo final pelo médico patologista | O sistema deve permitir que o médico patologista registre o laudo final, sincronizando-o com o AGHU. | Essencial |
| RF041 | Liberação de resultado no sistema | O sistema deve permitir que o médico patologista libere o resultado do exame, acionando a marcação automática como liberado. | Essencial |
| RF042 | Marcação automática como liberado | Após a liberação pelo médico patologista, o sistema deve marcar automaticamente o exame como liberado, sem necessidade de ação manual adicional. | Essencial |
| RF043 | Encaminhamento de lâminas para arquivamento | O sistema deve registrar o encaminhamento das lâminas para o arquivo físico após a liberação do laudo. | Essencial |

### 1.6 Rastreabilidade e Visão Unificada

| ID | Título | Descrição | Prioridade |
| :--- | :--- | :--- | :--- |
| RF044 | Histórico completo de movimentação | O sistema deve manter e exibir o histórico completo de todas as etapas pelas quais cada peça, cassete, bloco e lâmina passou, incluindo responsável e timestamp de cada transição. | Essencial |
| RF045 | Visão unificada | O sistema deve exibir uma tela unificada cruzando o histórico local de movimentação com os dados clínicos do AGHU em tempo real. O acesso pode ser feito por escaneamento do QR Code de qualquer subproduto (frasco, cassete, bloco ou lâmina) ou por busca manual via identificador ou número de solicitação. | Essencial |
| RF046 | Consulta de status atual da peça | O sistema deve permitir consultar em qual etapa do fluxo uma peça ou subproduto se encontra atualmente, via leitura de QR Code ou busca manual por número de solicitação, identificador do subproduto, CNS ou CPF do paciente. | Essencial |
| RF047 | Alertas de prazo | O sistema deve emitir alertas quando uma peça ou subproduto estiver retido em uma etapa além do prazo esperado. | Importante |

### 1.7 Busca e Pesquisa no Acervo

| ID | Título | Descrição | Prioridade |
| :--- | :--- | :--- | :--- |
| RF048 | Busca por número de solicitação | O sistema deve permitir a busca de exames pelo número de solicitação gerado na triagem. | Essencial |
| RF049 | Busca por dados do paciente | O sistema deve permitir a busca de exames por CNS, CPF ou nome do paciente. | Essencial |
| RF050 | Busca por período | O sistema deve permitir filtrar exames por intervalo de datas (recebimento, macroscopia, liberação). | Essencial |
| RF051 | Busca por tipo de peça | O sistema deve permitir filtrar exames pelo tipo de peça patológica. | Importante |
| RF052 | Busca por diagnóstico associado | O sistema deve permitir filtrar exames por diagnóstico registrado no AGHU. | Importante |
| RF053 | Busca por marcadores/complementos | O sistema deve permitir filtrar exames que tiveram imunohistoquímica ou complementos solicitados, com opção de filtrar pelo tipo de marcador. | Importante |
| RF054 | Exportação de resultados de busca | O sistema deve permitir exportar os resultados de uma busca para uso em pesquisa científica. | Desejável |

### 1.8 Integração com AGHU

| ID | Título | Descrição | Prioridade |
| :--- | :--- | :--- | :--- |
| RF055 | Importação de dados do paciente do AGHU | O sistema deve importar em tempo real dados clínicos e cadastrais do paciente a partir do AGHU, sem replicar ou armazenar laudos oficiais. | Essencial |
| RF056 | Importação de dados do exame do AGHU | O sistema deve importar os dados do exame registrado no AGHU para compor a visão unificada. | Essencial |
| RF057 | Escrita de dados no AGHU | O sistema deve enviar ao AGHU os registros de macroscopia, laudo prévio e laudo final conforme produzidos. A redação, assinatura digital e liberação oficial dos laudos permanecem exclusivamente no AGHU. | Essencial |

| ID | Título | Descrição | Prioridade |
| :--- | :--- | :--- | :--- |
| RF058 | Integração com impressora térmica | O sistema deve se comunicar diretamente com impressoras térmicas Zebra/Argox para impressão automatizada de etiquetas resistentes ao longo do processamento. | Essencial |

## 2. Requisitos Não Funcionais (RNF)

| ID | Categoria | Descrição |
| :--- | :--- | :--- |
| RNF001 | Segurança | Toda comunicação entre usuário e servidor deve ser criptografada via TLS. Dados sensíveis em repouso devem usar criptografia AES-256. |
| RNF002 | Segurança | Tokens de autenticação devem ser JWT com expiração configurável e renovação por refresh token. |
| RNF003 | LGPD | O sistema deve manter log de auditoria de todos os acessos e alterações em dados sensíveis de pacientes, com registro de usuário, ação, timestamp e IP. |
| RNF004 | LGPD | O sistema não deve armazenar dados além do necessário para a operação definida no escopo. Laudos oficiais permanecem exclusivamente no AGHU. |
| RNF005 | Disponibilidade | O sistema deve ter disponibilidade mínima de 99% durante o horário de operação do laboratório. |
| RNF006 | Desempenho | A leitura de QR Code e exibição da visão unificada devem ocorrer em no máximo 2 segundos em condições normais de rede. |
| RNF007 | Desempenho | Buscas no acervo com filtros simples devem retornar resultados em no máximo 3 segundos. |
| RNF008 | Usabilidade | A interface deve ser responsiva e utilizável em tablets e estações desktop, dado o contexto de uso em bancada de laboratório. |
| RNF009 | Usabilidade | Ações críticas (como confirmar identidade de uma lâmina ou liberar laudo) devem exigir confirmação explícita do usuário para evitar erros acidentais. |
| RNF010 | Rastreabilidade | Nenhuma transição de etapa pode ocorrer sem registro de usuário autenticado e timestamp, garantindo auditabilidade completa do fluxo. |
| RNF011 | Integridade | O sistema deve impedir a duplicidade de identificadores de peças, cassetes, blocos e lâminas. |
| RNF012 | Integração | A comunicação com o AGHU deve tratar falhas de conectividade com retry automático e alertas ao usuário em caso de indisponibilidade prolongada. |
| RNF013 | Manutenibilidade | O sistema deve ser desenvolvido com separação clara de camadas (API, serviço, persistência) para facilitar manutenção e evolução futura. |
| RNF014 | Compatibilidade | O sistema deve ser compatível com os navegadores modernos utilizados nas estações do hospital (Chrome e Firefox nas versões dos últimos 2 anos). |
| RNF015 | Hardware | O sistema deve ser compatível com os modelos de impressoras térmicas Zebra e Argox utilizados no laboratório. |
| RNF016 | Hardware | O sistema deve ser compatível com leitores de código de barras/QR Code (pistolas) HID (Human Interface Device), sem necessidade de driver adicional. |
